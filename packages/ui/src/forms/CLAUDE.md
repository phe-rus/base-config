# CLAUDE.md: `packages/ui/src/forms`

Loads when working under `packages/ui/src/forms/`: the `useAppForm`-based form field system. See `packages/ui/CLAUDE.md` for this package's other conventions.

`context.ts` wires up `createFormHook`/`createFormHookContexts` from `@tanstack/react-form`, `useAppForm`, `fieldContext`/`useFieldContext`, `formContext`/`useFormContext`. `fields/index.ts` exports the `fields` map (`useAppForm`'s `fieldComponents`) and `controls/index.ts` exports `formComponents` (`Subscribe`, a loading-state submit button wrapper).

**Every field component lives in its own folder**, `fields/<Name>/index.tsx` (Payload's own `packages/ui/src/fields/<Name>/` convention), plus a `fields/shared/` folder for cross-field helpers (`field-shell.tsx`, `FieldShell`/`RequiredMark`, `types.ts`, `BaseFieldProps`/`SelectOption`, `use-field-state.ts`, the hook every field calls to read/write its own value via TanStack Form's field context). No `index.css` per field (Payload's own convention rides on CSS Modules; this codebase uses Tailwind utility classes inline, an empty CSS file per field would be hollow mimicry).

Current field vocabulary, **every one of these now has a matching `FieldConfig` union entry in `@baseconfig/core`** (`packages/config/src/fields/types.ts`, see `packages/config/src/fields/CLAUDE.md`):

- **Original 12**: `Array` (ArrayField, recursive, drag-to-reorder via `@base-ui/react`'s primitives, per-row duplicate that deep-clones an item in place right below it plus delete), `Checkbox`, `Combobox` (single-select searchable), `DatePicker`, `Input` (generic text/password/etc, the `type` prop plus a built-in show/hide toggle when `type='password'`), `KeywordsInput`, `RadioGroup`, `RichText` (wraps `@baseconfig/ui/basiccn`'s `Editor`), `Select`, `Switch`, `Textarea`, `Upload` (`Media` was an early, `useUpload`-hook-driven duplicate of this exact "upload or browse existing" idea with no live caller anywhere; removed once it became clear `Upload`, wired everywhere, was the one actually adopted).

**`ArrayField`'s collapsed row chrome is shared by every array consumer** (`LinksField`, `NavMenu`, `BlocksField`): the drag handle and a trailing three-dots action menu (`../../components/dropdown-menu.tsx`, a `@base-ui/react/menu` wrapper) holding Move up / Move down (disabled at the edges), Duplicate, and a destructive Delete, replacing the old copy/delete button pair. Both the handle ("Drag to reorder") and the menu trigger ("Row options") sit inside `Tooltip` (`components/tooltip.tsx`, a `@base-ui/react/tooltip` wrapper). Two extension props exist for consumers that want a different collapsed row: `renderItemHeader({path, index, item})` replaces the label span entirely (keeps the shared drag + menu chrome, `BlocksField` renders its index/slug/editable-block-header stack through it), and `addAtBottom` moves a custom `renderAdd` row from above the list to below it (the default "Add items" row stays at the top either way).
- **Leaf-value fields**: `Email`/`Password`/`Slug` (thin presets over `Input`, fixed `type`/icon, no separate value handling, safe to wrap because `useFieldState()` resolves by the enclosing `form.AppField`'s context, not by which component happens to call the hook), `ConfirmPassword` (a thin preset over `Password`, the "must match" rule is deliberately *not* this component's job, since it can never see a sibling field's value; that's a consumer-level whole-object `.refine()`), `Number`/`Point`/`JSON` (real, non-preset implementations, a native `<input>`'s `value`/`e.target.value` is always a string even with `type='number'`, so `Number`/`Point` use `e.target.valueAsNumber`; `JSON`'s field value is the *parsed* value, with its own local "raw text being typed" state kept separate from the committed value, only committing valid JSON on blur), `Hidden` (no `FieldShell` chrome, just `<input type="hidden">`), `Code` (a real CodeMirror 6 editor with an inline corner language toggle, thin wrapper around `components/code-editor.tsx`'s `CodeEditor`, saves a plain string; superseded its original "monospace `Textarea`, no highlighting" implementation). **`Code` and `JSON` share the same `CodeEditor`**, the real difference is what gets committed, not styling: `Code` passes its string straight through (plus a language toggle, `languages`/`onLanguageChange` props, and an `onValueChange` callback so a caller like `@baseconfig/core`'s `code` block can react to keystrokes for its own auto-detect logic); `JSON` fixes the editor to `language='json'` with no toggle (`languages={[]}`) and keeps its own local text state, only calling `handleChange` with genuinely parsed JSON on blur, typing something momentarily invalid never corrupts the real field value.
- **Deliberately not added as `packages/ui` components**: `Blocks`/`Relationship` (already exist correctly, one layer up in `@baseconfig/core`'s own `collections/fields/` folders, app-specific composites dispatched via `define.ts`'s resolver maps, not generic `packages/ui` primitives); `Group`/`Row`/`Collapsible`/`Tabs`-as-a-field/`UI` (Payload's own layout/grouping types, these exist as `@baseconfig/core`'s own `fields/renderer.tsx` render branches, not `packages/ui` components; they need no field *value* state of their own, only layout chrome around already-independent child fields, so there's nothing for a `packages/ui/forms` component to own, see `packages/config/src/fields/CLAUDE.md`); `Join` (virtual/computed, needs real query-layer support first, not just a field type); `Null` (Payload-internal utility type, no clear equivalent need yet).
- **A component named after a JS global shadows that global for its whole module, including inside its own function body.** `export const Number = (...)` / `export const JSON = (...)` mean `Number.isNaN(...)`/`JSON.stringify(...)` *inside those components' own bodies* would silently try to call a method on the component function itself, a real runtime `TypeError`, not something TypeScript catches. Both use `globalThis.Number`/`globalThis.JSON` instead. Worth remembering for any future field named after a JS global (`Array`, `Object`, `Map`, `Set`, `Date`, …).
