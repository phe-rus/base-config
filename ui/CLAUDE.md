# CLAUDE.md — `base/ui`

Guidance specific to `base/ui/src/` — loads only when a session is working with files under this directory. See the root `CLAUDE.md` for the rest of the monorepo.

### The `base/ui` package (`base/ui/src/`)

The sibling library to `@base/config` — deliberately **decoupled from `@pherus/ui`** (2026-07-27): it vendors its own copies of the shadcn/base-ui primitives it needs, rather than importing a specific consumer's design system. Theming/styling stays the *consumer's* responsibility — `base/ui`'s components use plain Tailwind utility classes referencing CSS custom properties (`bg-primary`, `text-destructive`, etc.); any consumer with a compatible Tailwind+shadcn setup (a real CSS variable for each token) makes them render correctly, regardless of which package actually defines those variables. `base/config` also fully migrated off `@pherus/ui` onto `@base/ui`'s own vendored primitives — see `base/config/CLAUDE.md`.

```
base/ui/src/
  components/         vendored shadcn/base-ui primitives — badge, breadcrumb, button, calendar, checkbox, collapsible, combobox, dialog, drawer, field, input, input-group, label, popover, radio-group, select, separator, skeleton, sonner, switch, table, tabs, textarea. Copied from shared/ui/src/components/*.tsx, internal cross-imports rewritten to relative paths (e.g. field.tsx's own `label`/`separator` imports) — no @pherus/ui import anywhere in this package. `sonner.tsx` wraps `goey-toast` (a real dependency, not a vendored shadcn primitive). `code-editor.tsx` is the odd one out — not a vendored shadcn primitive but a real, form-agnostic CodeMirror 6 wrapper (`CodeEditor`, `@uiw/react-codemirror` + `@codemirror/{lang-javascript,lang-json,view}` — genuinely dependencies of this package now, chosen over Monaco specifically for bundle weight), exported as `@base/ui/components/code-editor` for reuse outside `@base/ui/forms` too (`@base/config`'s `code` block uses it directly for its own corner language toggle — see `base/config/CLAUDE.md`'s "Page-content blocks"). See "Form fields" below for the `Code`/`JSON` fields built on top of it.
  lib/utils.ts        cn() — clsx + tailwind-merge, vendored the same way
  basiccn/            the tiptap v3 rich text editor — see "Rich text" below. Exported as `@base/ui/basiccn` / `@base/ui/basiccn/preview`.
  forms/              the useAppForm-based form field system — see "Form fields" below. Exported as `@base/ui/forms`.
  tables/             tanstack-table wrapper (DataTable, pagination). Exported as `@base/ui/tables`.
  image/              TanstackImage. Exported as `@base/ui/image`.
```

No bare `.` root export — every subpath is explicit (`@base/ui/forms`, `@base/ui/basiccn`, etc.), matching the old `@pherus/utilities`'s own subpath-only convention. `@base/ui/components/*` and `@base/ui/lib/*` are also real exports (for anything that needs a vendored primitive directly), though nothing outside `base/ui` itself currently imports them that way — `base/config`/`www` reach the primitives indirectly through `@base/ui/forms` field components (and directly via `@base/ui/components/*` for the admin UI shell).

**Real Tailwind v4 gotcha, already fixed but worth knowing**: `shared/ui/src/styles/globals.css` (the one stylesheet `www` actually imports) uses explicit `@source` directives to tell Tailwind's scanner which directories to pull utility classes from — adding the new `base/` workspace directory required adding `@source "../../../../base/**/*.{ts,tsx}";` there. Without it, any class used only inside `base/ui`/`base/config` (not also used somewhere in `www`/`shared`) would be silently purged from the compiled CSS. Verify this kind of thing with a real check — grep the *built* CSS output for a distinctive class — not just "the build didn't error."

**Icon convention: `@tabler/icons-react` only, zero `lucide-react`.** `base/ui` was fully swept (2026-07-27) — every icon import across the whole package (fields, tables, basiccn) uses tabler; `lucide-react` isn't even a dependency anymore. `shared/utilities`/`shared/basiccn` (the old, now-inert originals) still have some `lucide-react` usage — irrelevant, since nothing imports them anymore.

#### Form fields (`@base/ui/forms`)

`context.ts` wires up `createFormHook`/`createFormHookContexts` from `@tanstack/react-form` — `useAppForm`, `fieldContext`/`useFieldContext`, `formContext`/`useFormContext`. `fields/index.ts` exports the `fields` map (`useAppForm`'s `fieldComponents`) and `controls/index.ts` exports `formComponents` (`Subscribe` — a loading-state submit button wrapper).

**Every field component lives in its own folder**, `fields/<Name>/index.tsx` (Payload's own `packages/ui/src/fields/<Name>/` convention, applied 2026-07-27 — previously flat, one file per field), plus a `fields/shared/` folder for cross-field helpers (`field-shell.tsx` — `FieldShell`/`RequiredMark`, `types.ts` — `BaseFieldProps`/`SelectOption`, `use-field-state.ts` — `useFieldState()`, the hook every field calls to read/write its own value via TanStack Form's field context). No `index.css` per field (Payload's own convention rides on CSS Modules; this codebase uses Tailwind utility classes inline — an empty CSS file per field would be hollow mimicry).

Current field vocabulary (not all of these have a corresponding `FieldConfig` union entry yet in `base/config` — see `base/config/CLAUDE.md`'s "Field types"):

- **Original 13**: `Array` (ArrayField — recursive, drag-to-reorder via `@base-ui/react`'s primitives), `Checkbox`, `Combobox` (single-select searchable), `DatePicker`, `Input` (generic text/password/etc — the `type` prop plus a built-in show/hide toggle when `type='password'`), `KeywordsInput`, `Media`, `RadioGroup`, `RichText` (wraps `@base/ui/basiccn`'s `Editor`), `Select`, `Switch`, `Textarea`, `Upload`.
- **Added 2026-07-27, Payload-parity leaf-value fields only**: `Email`/`Password`/`Slug` (thin presets over `Input` — fixed `type`/icon, no separate value handling; safe to wrap because `useFieldState()` resolves by the enclosing `form.AppField`'s context, not by which component happens to call the hook), `ConfirmPassword` (a thin preset over `Password` — the "must match" rule is deliberately *not* this component's job, since it can never see a sibling field's value; that's a consumer-level whole-object `.refine()`, same pattern `www/src/routes/(auth)/auth/create-account.tsx` already uses outside this generic system), `Number`/`Point`/`JSON` (real, non-preset implementations — a native `<input>`'s `value`/`e.target.value` is always a string even with `type='number'`, so `Number`/`Point` use `e.target.valueAsNumber`; `JSON`'s field value is the *parsed* value, with its own local "raw text being typed" state kept separate from the committed value, only committing valid JSON on blur), `Hidden` (no `FieldShell` chrome, just `<input type="hidden">`), `Code` (a real CodeMirror 6 editor with an inline corner language toggle — thin wrapper around `components/code-editor.tsx`'s `CodeEditor`, saves a plain string; superseded its original "monospace `Textarea`, no highlighting" implementation). **`Code` and `JSON` share the same `CodeEditor`** — the real difference is what gets committed, not styling: `Code` passes its string straight through (plus a language toggle, `languages`/`onLanguageChange` props, and an `onValueChange` callback so a caller like `@base/config`'s `code` block can react to keystrokes for its own auto-detect logic); `JSON` fixes the editor to `language='json'` with no toggle (`languages={[]}`) and keeps its own local text state, only calling `handleChange` with genuinely parsed JSON on blur — typing something momentarily invalid never corrupts the real field value.
- **Deliberately not added**: `Blocks`/`Relationship` (already exist correctly, one layer up in `base/config/src/collections/fields/` — app-specific composites dispatched via `define.ts`'s resolver maps, not generic `base/ui` primitives); `Group`/`Row`/`Collapsible`/`Tabs`-as-a-field/`UI` (Payload's own layout/grouping types — these now exist, but as `base/config/src/fields/renderer.tsx`'s own render branches, not `base/ui` components; they need no field *value* state of their own, only layout chrome around already-independent child fields, so there's nothing for a `base/ui/forms` component to own — see `base/config/CLAUDE.md`'s "Field types"); `Join` (virtual/computed, needs real query-layer support first, not just a field type); `Null` (Payload-internal utility type, no clear equivalent need yet).
- **A component named after a JS global shadows that global for its whole module, including inside its own function body.** `export const Number = (...)` / `export const JSON = (...)` mean `Number.isNaN(...)`/`JSON.stringify(...)` *inside those components' own bodies* would silently try to call a method on the component function itself — a real runtime `TypeError`, not something TypeScript catches. Both use `globalThis.Number`/`globalThis.JSON` instead. Worth remembering for any future field named after a JS global (`Array`, `Object`, `Map`, `Set`, `Date`, …).

#### Rich text (`@base/ui/basiccn`)

Tiptap v3, built up from individual extensions rather than `@tiptap/starter-kit` — every mark/node in the schema is one explicit import in `utils/extensions.ts`. No Yjs/collaboration.

- **Layout**: `index.ts` (barrel — `Editor`, `BasiccnContent`, `basiccnTheme`), `editor.tsx` (the editable `Editor`), `preview.tsx` (read-only `Preview`, `editable: false`), `theme.ts` (the `typeset`-based class list), `types.ts`, `components/` (bubble menu, popovers, link hover card, slash menu), `utils/` (extension list, custom `Indent` extension, color/font-family palettes), `nodes/`, `plugins/`.
- **Theming rides on `@pherus/ui`'s own `typeset` utility** (`shared/ui/src/styles/typeset.css`, loaded globally via `@pherus/ui/globals.css`, the one stylesheet `www` imports) — this is the one place `base/ui`'s own rendered output still depends on the *consumer's* specific CSS, by design (typography rules are a styling concern, same "theming is the consumer's job" boundary as everywhere else in this package).
- **`BasiccnContent` is tiptap JSON**, not a serialized-string format — flows through `Editor`'s `value`/`onChange` and `@base/ui/forms`' `RichText` field. Persisted server-side as-is inside a document's `data` (see `base/config/CLAUDE.md`'s "Content persistence") — no separate serialization step.
- **Bubble menu, and a known tiptap/portal gotcha**: `components/bubble-menus.tsx` renders `@tiptap/react/menus`' `BubbleMenu`, plus a nested "More" popover and a link popover, each using the vendored `Popover`. Tiptap's `BubbleMenu` hides itself on editor blur unless the blur-causing mousedown happened inside the menu's own DOM subtree — and `PopoverContent`/`SelectContent`/`ComboboxContent` all render through a React portal, never a DOM descendant of the bubble menu. The fix is a `pinnedCount` ref in `BubbleMenus`, threaded via an `onPinChange(open)` callback; a custom `shouldShow` stays `true` while `pinnedCount > 0`. **Any new popover/select/combobox nested inside the bubble menu must call this callback on open/close.**
- **Watch for duplicate-registration crashes** when adding extensions: two extensions claiming the same ProseMirror plugin key throw `RangeError` at mount; two claiming the same *node* name only warn, second silently wins. Check `BasiccnExtensions` in `utils/extensions.ts` first.
- **`Placeholder`, `Gapcursor`, `Dropcursor`, `CharacterCount`, `UndoRedo`** all come from the single `@tiptap/extensions` package. **`TextStyleKit`** is configured with `fontSize`/`lineHeight`/`backgroundColor` all `false` (it already bundles `Color`+`FontFamily`).
- **Consumer**: `@base/ui/forms`'s `RichText` field (`fields/RichText/index.tsx`) is the only importer of `Editor`. No admin route imports it directly — collection editing is generic (`CollectionForm`).
